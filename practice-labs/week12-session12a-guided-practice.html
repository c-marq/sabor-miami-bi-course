Building the Sabor Miami Star Schema

Chapter 8: Data Modeling Fundamentals  |  Time Estimate: 20–25 minutes  |  12 Steps across 4 Phases

🚀 LAUNCH PAD

What you are building: The complete Sabor Miami data model — relationships between your tables configured and verified in Model View

Tool: Power BI Desktop → Model View (primary), Report View (verification)

File to open: Your Lab #2 file (LastName_FirstName_Lab2.pbix)

Time estimate: 20–25 minutes

Steps: 12 steps across 4 phases

What "done" looks like: A star-shaped model in Model View with Sales in the center, connected to Trucks, Menu Items, and Employees — and two table visuals in Report View confirming the relationships work

Start here → Open your Lab #2 .pbix file and make sure you are in the main Power BI Desktop window (dark blue or gray ribbon — NOT the green Power Query ribbon)

💡 WHY ARE WE DOING THIS?

In Lab #2, you merged columns from Trucks, Menu Items, and Employees into the Sales table. That brought descriptive data (like truck_name and item_name) directly into Sales so you could inspect it and build visuals.

But here is the key insight: those merged columns are for your convenience. The data model's relationships are for Power BI's engine.

When Power BI calculates a total, filters a chart, or answers a question like "Which truck sold the most?" — it does not use the merged columns. It uses relationships — the connections between the original tables.

Think of it this way:

  • Merged columns = you printed a copy of the truck name on every receipt (handy for reading)
  • Relationships = the cash register system knows which receipts belong to which truck (essential for calculating)

Both matter. But without relationships, Power BI's calculation engine has no way to connect your tables. That is what we build now.

Phase 1 of 4: Setup

Step 1: Open your file and switch to Model View

  1. Open your Lab #2 .pbix file in Power BI Desktop
  2. If you see a green ribbon at the top, you are still in the Power Query Editor — click Close & Apply on the Home tab to return to the main window
  3. Look at the left sidebar — you will see a vertical stack of small icons
  4. Click the third icon from the top — it looks like three small connected boxes. This is Model View

WHERE AM I? You should now see your tables as rectangular boxes on a canvas, with column names listed inside each box. The ribbon at the top should be dark blue or gray (not green).

Step 2: Identify your tables

Look at the canvas. You should see boxes for these tables:

  • sales — your fact table (the largest, with transaction data)
  • menu_items — menu item names, categories, prices
  • trucks — truck names, locations, statuses
  • employees — employee names, roles
  • events — event names, types, dates
🛑 STOP AND CHECK

Count the table boxes on your canvas. You should see 5 tables (sales, menu_items, trucks, employees, events). If any table is missing, go to Home tab → Transform Data to open Power Query, then verify that Enable Load is checked for all 5 tables. Click Close & Apply to return.

Step 3: Check for auto-detected relationships

Power BI sometimes auto-detects relationships based on matching column names. Look for lines connecting any of your table boxes.

  • If you see lines: Good — Power BI guessed some connections. We will verify and fix them in the next phase.
  • If you see no lines: That is also fine — we will create the relationships from scratch.
💡 WHY ARE WE DOING THIS?

Power BI's auto-detection is helpful but not always correct. It matches columns by name and data type, but it cannot know your business logic. We will verify every relationship it created — and fix anything it got wrong — rather than trusting it blindly.

Phase 2 of 4: Explore

Step 4: Arrange your tables in a star pattern

Before building relationships, let us organize the canvas so you can see the model clearly.

  1. Drag the sales table to the center of the canvas
  2. Drag trucks to the upper left
  3. Drag menu_items to the upper right
  4. Drag employees to the lower left
  5. Drag events to the lower right
💜 TAKE A BREATH

You just arranged your first data model layout. This star shape has a formal name — star schema — which you will learn about in Chapter 9. For now, the important thing is that your transaction table (sales) sits at the center, and the tables that describe those transactions surround it. That is the architecture of almost every analytics model in the professional world.

Step 5: Identify the key column pairs

Before dragging any lines, identify which columns connect each table to Sales. These are the shared key columns — the same column appearing in both tables:

Sales Column Connects To Dimension Column
truck_id trucks truck_id
menu_item_id menu_items menu_item_id
employee_id employees employee_id

These are the same foreign key → primary key connections you learned about in your database course. Same concept, visual interface.

Phase 3 of 4: Build

Step 6: Verify or create the Sales-to-Trucks relationship

If Power BI auto-detected this relationship (you see a line between sales and trucks):

  1. Double-click the line between sales and trucks to open the Edit Relationship dialog
  2. Verify these settings:
    • The matched columns are truck_id on both sides
    • Cardinality says Many to one (*:1)
    • Cross filter direction says Single
  3. If everything matches, click OK (or Cancel — no changes needed)
  4. If the columns or settings are wrong, correct them and click OK

If no line exists:

  1. Click on truck_id inside the sales table box
  2. Drag it to truck_id inside the trucks table box
  3. Release the mouse button — the Create Relationship dialog appears
  4. Confirm: Many to one (*:1) and Single cross filter direction
  5. Click OK
🛑 STOP AND CHECK

You should see a line between sales and trucks. The line should show a * (asterisk) on the sales side and a 1 on the trucks side. This means "many sales connect to one truck." If you see different symbols, double-click the line and check the cardinality setting.

⚠️ COMMON MISTAKE

The T005 orphan issue: Your sales table contains 2 rows that reference truck_id = T005 — but there is no Truck T005 in your trucks table. This is called an orphan record: a row that points to a value that does not exist in the related table.

You may not notice anything wrong right now — Power BI still creates the relationship. But those 2 orphan rows will not appear in visuals that use truck names (because there is no truck name to look up). We will address what to do about orphan records when we refine the model in a later chapter. For now, just know they exist.

Step 7: Verify or create the Sales-to-Menu Items relationship

Follow the same process as Step 6:

  1. If a line exists: Double-click it and verify menu_item_id on both sides, Many to one (*:1), Single
  2. If no line exists: Drag menu_item_id from sales to menu_item_id in menu_items. Confirm settings and click OK
🛑 STOP AND CHECK

You should now see 2 relationship lines radiating from the sales table — one to trucks and one to menu_items. Both should show *:1 (many-to-one) cardinality.

Step 8: Verify or create the Sales-to-Employees relationship

Follow the same process:

  1. If a line exists: Double-click and verify employee_id on both sides, Many to one (*:1), Single
  2. If no line exists: Drag employee_id from sales to employee_id in employees. Confirm settings and click OK
🛑 STOP AND CHECK

Your Model View should now show 3 relationship lines — sales connected to trucks, menu_items, and employees. The events table sits unconnected for now — that is correct. We will revisit the Events connection in a future session.

The overall shape should look like a star: sales in the center, three dimension tables around it, each connected by a single line.

Step 9: Configure column properties

Before verifying, let us clean up a few column settings so your model behaves correctly in reports.

For each dimension table (trucks, menu_items, employees), do the following:

  1. Click the ID column (e.g., truck_id in the trucks table)
  2. Look at the Properties pane on the right side of the screen
  3. Find Summarize by (it may say "Sum" by default) — change it to Don't Summarize
  4. Right-click the ID column → select Hide in report view

Repeat for:

  • truck_id in trucks
  • menu_item_id in menu_items
  • employee_id in employees

Also do this for the key columns in the sales table:

  • truck_id, menu_item_id, employee_id — set each to Don't Summarize and Hide in report view
💡 WHY ARE WE DOING THIS?

ID columns are identifiers — they label records, not quantities. Summing T001 + T002 + T003 produces a meaningless number. Setting "Don't Summarize" prevents Power BI from automatically summing them when you drag them into a visual. Hiding them from Report View keeps the Fields pane clean — report builders see truck_name (useful) instead of truck_id (not useful for visuals). The IDs still work behind the scenes for relationships.

Phase 4 of 4: Verify

💜 TAKE A BREATH

You have built the data model — three relationships connecting your Sales table to Trucks, Menu Items, and Employees. The star shape is visible. Column properties are configured. Now comes the payoff: you test whether the relationships actually work by building two quick visuals.

Step 10: Switch to Report View and test the Trucks relationship

  1. Click the Report View icon in the left sidebar — first icon from the top, looks like a bar chart
  2. In the Visualizations pane (right side of the screen), click the Table visual icon — it looks like a small grid
  3. An empty table visual appears on the canvas
  4. In the Data pane (far right), expand the trucks table
  5. Check the box next to truck_name — it appears in the table visual
  6. Expand the sales table
  7. Check the box next to amount — Power BI automatically sums it for each truck
🛑 STOP AND CHECK

Your table visual should show 4 rows — one for each Sabor Miami truck — with different sales amounts for each truck.

✅ 4 rows with different amounts = Your Sales-to-Trucks relationship is working. Power BI knows which sales belong to which truck. 🎉

❌ 1 row with a grand total = The relationship is missing. Go back to Model View and verify you created a relationship between sales[truck_id] and trucks[truck_id].

❌ 4 rows with the SAME amount = The relationship is connecting the wrong columns. Double-click the relationship line in Model View and check that truck_id is matched on both sides.
