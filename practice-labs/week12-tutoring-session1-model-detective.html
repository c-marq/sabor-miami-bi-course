🚀 LAUNCH PAD

What you are building: A star schema data model for a Miami-Dade County library checkout dataset — a dataset you have never seen before

Tool: Power BI Desktop → Power Query (load only), Model View (build), Report View (verify)

Files to open: 4 CSV files — MiamiDade_Library_Checkouts.csv, MiamiDade_Library_Books.csv, MiamiDade_Library_Branches.csv, MiamiDade_Library_Patrons.csv

Time estimate: 50–60 minutes

Steps: 16 steps across 4 phases

What "done" looks like: A four-table star schema with the fact table in the center, three dimension tables connected by relationships, verified with two table visuals

Start here → Open Power BI Desktop and create a new blank report

💡 WHY ARE WE DOING THIS?

In Session 12A, you built the Sabor Miami star schema — but the instructor told you which table was the fact table and which columns to connect. In a real job, nobody tells you. You open a dataset and figure it out yourself.

This exercise gives you that experience with a dataset you have never seen before. By the end, you will have proven to yourself that you can look at any set of tables and identify the fact table, the dimensions, the keys, and the relationships — without anyone telling you.

Phase 1 of 4: Load the Data

Step 1: Open Power BI and connect to the CSV files

  1. Open Power BI Desktop and create a new blank report
  2. Click Home tab → Get Data → Text/CSV
  3. Navigate to the folder containing the 4 library CSV files
  4. Select MiamiDade_Library_Checkouts.csv and click Open
  5. In the preview window, verify the data looks correct, then click Load (not Transform Data — this data is already clean)
  6. Repeat steps 2–5 for the remaining three files:
    • MiamiDade_Library_Books.csv
    • MiamiDade_Library_Branches.csv
    • MiamiDade_Library_Patrons.csv
🛑 STOP AND CHECK

In the Data pane (right side of the screen), you should see 4 tables: MiamiDade_Library_Checkouts, MiamiDade_Library_Books, MiamiDade_Library_Branches, and MiamiDade_Library_Patrons.

Step 2: Explore each table in Table View

Switch to Table View (second icon on the left sidebar). Click on each table in the Data pane and look at the columns and rows. For each table, note:

  • How many rows does it have? (Check the status bar at the bottom)
  • What do the columns contain?
  • Does each row represent an event (something that happened) or a description (something that exists)?

Phase 3 of 4: Build the Star Schema

Step 7: Switch to Model View and arrange your tables

  1. Click the Model View icon (third icon on the left sidebar — three connected boxes)
  2. Drag the fact table to the center of the canvas
  3. Drag the three dimension tables around it — one above, one to the left, one to the right

Step 8: Delete any auto-detected relationships

Power BI may have auto-detected some relationships. For this exercise, we want you to build from scratch so you can verify your predictions.

  1. If you see any relationship lines between tables, right-click each line
  2. Select Delete
🛑 STOP AND CHECK

You should see 4 table boxes on the canvas with no lines between them. The fact table should be in the center.

Step 9: Configure ID columns

Before creating relationships, set the ID columns to Don't Summarize and Hide in report view. Do this for every ID column across all 4 tables (both the primary keys in dimension tables and the foreign keys in the fact table).

Step 10: Create the first relationship

Using the key column pairs you identified in Step 5, create your first relationship:

  1. Drag the key column from the fact table to the matching column in the first dimension table
  2. In the Create Relationship dialog, verify: Many to one (*:1) and Single cross filter direction
  3. Click OK

Step 11: Create the remaining relationships

Repeat the process for the other two dimension tables. For each one, drag the key column from the fact table to the matching column in the dimension table, verify Many to one (*:1) and Single, and click OK.

🛑 STOP AND CHECK

Your Model View should now show 3 relationship lines radiating from the fact table to the three dimension tables. Each line should show *:1 cardinality. The overall shape should look like a star.

Phase 4 of 4: Verify

Step 12: Test the Branches relationship

  1. Switch to Report View (first icon on the left sidebar)
  2. Click the Table visual icon in the Visualizations pane
  3. From the Branches table, check branch_name
  4. From the Checkouts table, check checkout_id — Power BI will count it
🛑 STOP AND CHECK

You should see 5 rows — one per branch — with different checkout counts. Different counts = the relationship is working.

Step 13: Test the Books relationship

  1. Click an empty area on the canvas to deselect
  2. Create a second Table visual
  3. From Books, check title
  4. From Checkouts, check late_fee — Power BI will sum it

This visual should show each book title with a different total late fee amount. Some books may show $0.00 (no late returns for that title).

Step 14: Test the Patrons relationship

  1. Click an empty area to deselect
  2. Create a third Table visual
  3. From Patrons, check membership_type
  4. From Checkouts, check checkout_id — Power BI will count it
