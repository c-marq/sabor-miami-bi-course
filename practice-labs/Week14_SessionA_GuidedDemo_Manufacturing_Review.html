Phase 2 · Fix the Two-Header-Row Problem
⏱ About 10 minutes · Reviews: Week 8 profiling + Week 9 cleaning
💡 WHY does this file need a header fix?
Look at row 1 of your data. You should see short codes like GEO_ID, NAICS2017, PAYANN. Now look at row 2 — you should see descriptive labels like Geographic Area Name, Annual payroll ($1,000). Both rows look like headers! This dataset came from the US Census Bureau, and they packed two header rows into the file. We need the descriptive labels as our column names, not the codes. That takes four moves.
✅ DO THIS — The Four-Move Header Fix
  1. Move 1 — Demote the current headers. Right now Power BI auto-promoted the short codes (GEO_ID, NAICS2017…) as column headers. Go to the Transform tab in the top ribbon → click the dropdown arrow under Use First Row as Headers → choose Use Headers as First Row. The short codes should drop down into row 1 of the data, and your headers should now read Column1, Column2, etc.
  2. Move 2 — Remove the short-code row. On the Home tab → Remove Rows → Remove Top Rows. Enter 1 and click OK. The short codes row is gone. Row 1 should now be the descriptive labels.
  3. Move 3 — Promote the descriptive labels. On the Home tab → click Use First Row as Headers. Your column headers should now read id, Geographic Area Name, Geo Footnote, and so on.
  4. Move 4 — Look at the Applied Steps pane on the right. You should see: Source → Promoted Headers (from auto-load) → Changed Type → Demoted Headers → Removed Top Rows → Promoted Headers. Every move you made is a line in that list. This is the thing that makes Power Query powerful — it remembers everything.
⚠️ COMMON MISTAKE
Students skip Move 1 (demoting) and try to go straight from "short code headers" to "descriptive label headers." It does not work because Use First Row as Headers promotes the first data row — and right now your first data row is the descriptive labels, but Power BI does not know that yet. Demoting first is the trick. Write this down: when you need to swap headers, demote before you promote.
🛑 STOP AND CHECK
Look at your column headers. The second column should read Geographic Area Name, not NAME. The column that was PAYANN should now read Annual payroll ($1,000). If you still see the short codes, you skipped a move. Raise your hand.

Phase 3 · Fix Data Types
⏱ About 8 minutes · Reviews: Week 9 cleaning — data type errors
💡 WHY do data types matter?
Power Query guesses data types when it loads a file. Most of the time it guesses right. Sometimes it guesses wrong — and a wrong guess quietly breaks things downstream. A classic example: an ID column that is actually a label (like 31-33) gets guessed as a whole number and loses the dash. Or NAICS codes lose their leading zeros. Fixing types early saves pain later.
✅ DO THIS
  1. Scroll across your query and look at the small icon next to each column header. ABC = text. 1.2 = decimal. 123 = whole number. 📅 = date.
  2. Find the Industry group column. Power BI likely guessed it as whole number. Click the icon next to "Industry group" and choose Text.
  3. When the "Change Column Type" dialog appears, click Replace Current (not Add New Step). We want to fix the existing type conversion, not stack a second one on top.
  4. Do the same check on 2017 NAICS code — it should be Text, not whole number. If it is already text, leave it alone.
  5. Verify that Annual payroll ($1,000) and Number of employees are both typed as Whole Number. These are the values we will actually calculate on later.
⚠️ COMMON MISTAKE
Clicking Add New Step instead of Replace Current leaves a bad type conversion in your Applied Steps and stacks a correction on top of it. It works, but it is messy and slow. Always Replace Current when you are fixing Power BI's first guess.

Phase 4 · Transformations — Text Moves
⏱ About 10 minutes · Reviews: Week 10 transforming text
✅ DO THIS — Lowercase the NAICS meaning
  1. Find the column called Meaning of NAICS code. Click the column header once to select the whole column.
  2. Go to the Transform tab in the top ribbon → click Format → lowercase.
  3. Every value in that column should now be lowercase: manufacturing instead of Manufacturing.
✅ DO THIS — Add a "Code: " prefix to Industry group
  1. Click the header of the Industry group column to select it.
  2. Transform tab → Format → Add Prefix.
  3. In the dialog, type exactly: Code: (that is Code then a colon then a space). Click OK.
  4. Every value in Industry group should now start with Code: — for example, Code: 31-33.
💡 WHY two transformations that look small?
These are the two most common text moves you will ever make in Power Query: standardize casing and add context to codes. In a real job you will lowercase customer emails to match them, or prefix product IDs with their category. The point is not the lowercase itself — it is getting the muscle memory for where the Format menu lives.
🛑 STOP AND CHECK
Look at both columns. Meaning of NAICS code should be all lowercase. Industry group should start with Code: . If either one is wrong, click the X next to the bad step in Applied Steps (right side) to undo, and redo it.
Phase 5 · Transformations — One Math Move
⏱ About 7 minutes · Reviews: Week 10 transforming numerical data
💡 WHY take the log of payroll?
Annual payroll ranges from a few million dollars to hundreds of billions across the states. When you chart numbers with that kind of spread, California crushes every other state and you cannot see the pattern in the smaller ones. Taking the natural log flattens the scale so every state is visible. This is one of the most common tricks in data visualization, and Power Query can do it in two clicks.
✅ DO THIS
  1. Find the Annual payroll ($1,000) column. Click the header to select it.
  2. Important — we want to add a new column with the log, not replace the original. Go to the Add Column tab in the top ribbon (not Transform this time).
  3. Click Scientific → Natural Logarithm. A new column appears at the far right of the table, called something like Natural Logarithm.
  4. Double-click the header of that new column and rename it to ln_annual_payroll (all lowercase, underscore, no spaces).
⚠️ COMMON MISTAKE — Transform vs. Add Column
The Transform tab changes the existing column. The Add Column tab creates a new column and leaves the original alone. Students mix these up constantly. Rule of thumb: if you want to keep the original value AND have the transformed one, use Add Column. If you want to replace, use Transform. For the log, we always want the original payroll kept — so Add Column.
⚠️ Dr. Lee's warning about rounding
If you ever round numbers in Power Query, the rounding is permanent. The original value is gone. If you only want to display fewer decimals, do that in the report view, not Power Query. Power Query is where you change data; report view is where you change how data looks.
Phase 6 · Rename Columns to lowercase_underscore
⏱ About 10 minutes · Reviews: Week 9 naming conventions
💡 WHY rename everything?
Column names with spaces, parentheses, and dollar signs work, but they make DAX measures ugly and error-prone. SUM('manufacturing_data'[Annual payroll ($1,000)]) is a nightmare to type. SUM(manufacturing[annual_payroll_thousands]) is clean. This is the exact naming convention we have used all semester — today we prove we can apply it to a dataset we did not design.

Phase 7 · Close & Apply, then Fix the Data View
⏱ About 10 minutes · Reviews: Week 12 Data view settings
✅ DO THIS — Load the query
  1. On the Home tab of Power Query → click Close & Apply (top-left).
  2. Power BI will think for a few seconds while it loads. When it is done, you are back in the main Power BI window.
  3. Click the Data view icon on the far-left toolbar — it is the middle of three icons (Report view, Data view, Model view). Data view is the one that looks like a spreadsheet grid.
  4. In the Fields pane on the right, click manufacturing to open it. You should see all your renamed columns.
✅ DO THIS — Three Data view fixes
  1. Don't Summarize the sector code. Click on sector_code in the Fields pane. Go to the Column tools tab in the top ribbon. Find the Summarization dropdown → change it from "Sum" to Don't summarize. Do the same for subsector_code, naics_code, and year. These are labels that happen to be numbers — we do not want Power BI adding them up.
  2. Tag state_name as geography. Click state_name. In the Column tools tab → find Data category → change from "Uncategorized" to State or Province. This tells Power BI that these values are real US states and can be plotted on a map.
  3. Hide the footnote columns. In the Fields pane, right-click geo_footnote → Hide in report view. Do the same for naics_footnote. These columns are mostly null and would clutter any report.
💡 WHY Don't Summarize?
By default, Power BI assumes every numeric column is something you want to sum. But codes like 31 for Manufacturing are identifiers, not quantities. If you drop sector_code into a visual and Power BI adds them up, you get garbage numbers. Don't Summarize tells Power BI "treat this as a label, not a measure." This is a Week 12 move — we applied it to the IDs in Sabor Miami too.

In the Fields pane, state_name should have a small globe icon next to it, showing the geographic category is set. sector_code and year should have the Σ symbol removed (Don't Summarize). geo_footnote and naics_footnote should be grayed out (hidden).

Phase 8 · Verify and Save
⏱ About 5 minutes
✅ DO THIS — Quick sanity visual
  1. Click the Report view icon on the far-left toolbar (the top icon, looks like a bar chart).
  2. In the Visualizations pane on the right, click the Table visual icon (a small grid).
  3. With the table visual selected, check state_name and annual_payroll_thousands in the Fields pane. Both should appear in your table visual.
