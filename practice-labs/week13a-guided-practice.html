Phase 2 of 3 — Build Your Measures

Write Three Measures

Every measure follows the same workflow: ask the question in English → write the DAX → display it in a visual. You will repeat this workflow three times.

💡 MEASURES vs. CALCULATED COLUMNS

Last week you wrote formulas like Year = YEAR('Date'[Date]) on the Date table. Those were calculated columns — they created a new column visible in Table View, calculated once per row during data refresh.

Today's formulas look similar in the formula bar, but they are measures — they do NOT create a column. Instead, they create a calculation that Power BI runs on the fly whenever you put it in a visual. Measures respond to filters dynamically. You will see them in the Data pane with a calculator icon (not attached to a row of data).

Measure 1: Highest Sale

What we want to ask: "What is the largest single sale amount in the entire dataset?"

Highest Sale = MAX(sales[amount])

MAX looks through every value in the amount column and returns the single largest one.

✅ DO THIS

Step 4. In the Data pane (right side), click on the sales table name to select it. This tells Power BI which table will "own" your new measure.

Step 5. On the Home tab of the ribbon, click the New Measure button (in the Calculations group). The formula bar — the white text area below the ribbon — will activate with the cursor ready.

Step 6. Type the following exactly as shown, then press Enter:

Highest Sale = MAX(sales[amount])

Step 7. Now display it: In the Visualizations pane (right side, above the Data pane), click the Card visual icon — it looks like a single large number (123). An empty Card appears on the canvas.

Step 8. In the Data pane, expand the sales table. Find Highest Sale — it has a small calculator icon next to it (this icon means it is a measure, not a column). Drag Highest Sale into the Card visual, or check the box next to it while the Card is selected.

A number appears. That is the single largest transaction in the Sabor Miami dataset.

🛑 STOP AND CHECK

Your Card visual should display a number — this is the price of the most expensive single transaction. If you see the text "Highest Sale" but no number, make sure you dragged the measure (calculator icon), not the amount column (sigma Σ icon). If you see an error, click the Card and check the formula bar — the measure name must be on the left of the equals sign and the formula on the right.

⚠️ COMMON MISTAKE

"I clicked New Measure but nothing happened." — Make sure you clicked New Measure on the Home tab (or the Modeling tab), not "New Column." Both are in similar locations. New Measure creates a measure (calculator icon). New Column creates a calculated column (Σ icon) — that is not what we want here.

Measure 2: Lowest Sale

What we want to ask: "What is the smallest single sale amount in the dataset?"

Lowest Sale = MIN(sales[amount])

MIN is the opposite of MAX — it finds the single smallest value. If this number is negative, that is the refund transaction in the dataset. That is valid data, not an error.

✅ DO THIS

Repeat the same workflow:

  1. Click the sales table in the Data pane.
  2. Home tab → New Measure.
  3. Type Lowest Sale = MIN(sales[amount]) and press Enter.
  4. Create a new Card visual and drag Lowest Sale into it.
🛑 STOP AND CHECK

You should now have 2 Card visuals: Highest Sale and Lowest Sale. The Lowest Sale should be much smaller than Highest Sale. If Lowest Sale is negative, that is the refund in the dataset — it means the data is working correctly.

💜 TAKE A BREATH

Two measures done. You typed DAX in the formula bar, pressed Enter, and saw a number appear in a visual. That is the core DAX workflow — everything else in this chapter builds on exactly what you just did. One more measure to go.

Measure 3: Average Tip

What we want to ask: "What is the average tip amount per transaction?"

Average Tip = AVERAGE(sales[tip])

AVERAGE adds up all the values in the tip column and divides by the number of values. This gives you the typical tip per transaction.

✅ DO THIS
  1. Click the sales table → Home tab → New Measure.
  2. Type Average Tip = AVERAGE(sales[tip]) and press Enter.
  3. Create a new Card visual and drag Average Tip into it.
  4. Arrange all 3 Card visuals in a row across the top of your canvas.
🛑 STOP AND CHECK

You should have 3 Card visuals in a row: Highest Sale, Lowest Sale, Average Tip. Check these relationships between the numbers:

  • Highest Sale should be the largest number.
  • Lowest Sale should be the smallest (possibly negative if it is a refund).
  • Average Tip should be a small number — it is a per-transaction average, not a total.

If all three check out, you have your first working measures.

Phase 3 of 3 — See Filter Context in Action

Watch Your Measures Respond to Filters

Right now, your 3 Card visuals show values for all Sabor Miami data — every truck, every day, every transaction. But what happens when you add a filter?

✅ DO THIS

Step 8. Add a slicer to your page:

  1. In the Visualizations pane, click the Slicer icon — it looks like a funnel with horizontal lines.
  2. An empty slicer appears on the canvas.
  3. In the Data pane, expand the trucks table and drag truck_name into the slicer.
  4. You should see a list of truck names: La Havana Express, Sabor On Wheels, Caribbean Cruiser, The Plantain Express.

Now click on La Havana Express in the slicer. Watch all three Card visuals — every number changes. Click a different truck — the numbers change again. Clear the slicer by clicking the eraser icon (top-right corner of the slicer) to return to the full dataset.

💡 THAT IS FILTER CONTEXT

You wrote one Highest Sale measure. You did not write "Highest Sale for La Havana Express" and "Highest Sale for Caribbean Cruiser" separately. The slicer creates a filter context — it tells Power BI "only show me data for this truck." Your measure automatically calculates using only the filtered data. This is the most powerful idea in DAX: write the measure once, and the visual's filters determine which data it uses.

On Wednesday, you will write a measure using CALCULATE that overrides this filter — forcing a specific truck's sales even when the slicer says something different.
