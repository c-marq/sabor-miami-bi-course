You will perform 3 merges, each one connecting the Sales table to a dimension table using a shared key column. All three merges use the same technique: Merge Queries with a Left Outer join, then expand specific columns.

Every merge follows this pattern:

  1. Select Sales in the Queries pane
  2. Open the Merge Queries dialog
  3. Pick the dimension table and match the key columns
  4. Choose Left Outer join
  5. Expand only the columns listed below
  6. Uncheck "Use original column name as prefix"

Task 1 — Merge Sales with Menu Items (10 points)

Key: Menu_Item_ID Join: Left Outer Expand: Item_Name, Category
✅ DO THIS
  1. Click Sales in the Queries pane (left panel).
  2. Go to Home tab → Combine section → Merge Queries (click the top option, not "Merge Queries as New").
  3. The Merge dialog opens. The top table should show Sales.
  4. In the bottom dropdown, select MenuItems.
  5. In the Sales preview (top), click the Menu_Item_ID column header — it highlights green.
  6. In the MenuItems preview (bottom), click the Menu_Item_ID column header — it also highlights green.
  7. Confirm the Join Kind says Left Outer (all from first, matching from second).
  8. Click OK.
  9. A new column called MenuItems appears at the far right of Sales. Each cell says "Table."
  10. Click the expand button (the ↔ icon on the right side of the MenuItems column header).
  11. In the dropdown, uncheck "Use original column name as prefix."

Task 4 — Configure Loading (8 points)

Now you will control which queries load into the Power BI data model. The 5 original tables should all load. But first, you need to create a staging query and disable it — this demonstrates that you understand the difference between a loaded query and a staging query.

✅ DO THIS — Create a staging query
  1. Right-click Sales in the Queries pane.
  2. Select Reference. A new query called Sales (2) appears.
  3. Right-click Sales (2) and select Rename. Type Sales_Summary_ByTruck and press Enter.
  4. With Sales_Summary_ByTruck selected, go to Transform tab → Table section → Group By.
  5. In the Group By dialog:
    — Group by: Truck_ID
    — New column name: Total Sales
    — Operation: Sum
    — Column: Amount
  6. Click OK.
✅ DO THIS — Disable loading for the staging query
  1. Right-click Sales_Summary_ByTruck in the Queries pane.
  2. Click Enable Load to uncheck it.
  3. The query name should become italicized — this means it will NOT load into the data model.
💡 WHY ARE WE DOING THIS? In real projects, you often have helper queries that do intermediate work (summaries, filtered subsets, lookups) but should not clutter your data model. Disabling their load keeps the model clean — only the tables you actually need for reports and calculations appear in the Fields pane. The staging query still runs and can feed other queries, but it stays behind the scenes.
🛑 STOP AND CHECK — Loading Configuration Look at the Queries pane on the left. You should see:

✅ Sales — normal text (will load)
✅ MenuItems — normal text (will load)
✅ Trucks — normal text (will load)
✅ Employees — normal text (will load)
✅ Events — normal text (will load)
✅ Sales_Summary_ByTruck — italicized text (will NOT load)

If Sales_Summary_ByTruck is NOT italicized, right-click it and toggle Enable Load again.

Task 5 — Verify Row Counts (5 points)

✅ DO THIS
  1. Click Sales in the Queries pane.
  2. Look at the row count in the bottom-left corner of the Power Query Editor window.
  3. Compare this number to the row count you recorded in Phase 1, Step 2.
🛑 STOP AND CHECK — Row Count Verification Your Sales row count should be exactly the same as your starting row count.

A Left Outer join keeps ALL rows from the first table (Sales). It adds columns — it does not add or remove rows. If your row count changed, something went wrong with one of the merges. The most common cause: you accidentally used Merge Queries as New instead of Merge Queries, or you selected Inner join instead of Left Outer.

If the count does not match, check the Applied Steps pane for your merge steps and verify the join type on each one.

Troubleshooting

"I do not see the Merge Queries button." Make sure you are in the Power Query Editor (separate window with the green ribbon), not the main Power BI Desktop window. The Merge Queries button is on the Home tab of the Power Query Editor, in the Combine section.
"My columns say MenuItems.Item_Name instead of Item_Name." You left "Use original column name as prefix" checked during the expand step. You can fix this two ways: (1) double-click the column header and retype the shorter name, or (2) delete the "Expanded" Applied Step (click the X next to it) and redo the expand with the prefix unchecked.
"I see 'Error' in some cells after merging." This is different from seeing "null." Errors usually mean a data type mismatch between the key columns. Check that the key column in both tables has the same data type (both Text, or both Whole Number). You can check by clicking the icon next to the column header — it shows the data type.
"My row count is different after the merges." A Left Outer join should never change the row count of the first table. Check each merge step in the Applied Steps pane: click on the "Merged Queries" step and look at the bottom of the Merge dialog to see the join type. If any merge used Inner instead of Left Outer, delete that step and redo it.
"I clicked Merge Queries as New by accident." This creates a new separate query instead of adding the merge to Sales. Delete the new query (right-click → Delete), go back to Sales, and use Merge Queries (the top option, not "as New").
"Close & Apply is taking a very long time." This is normal if your dataset is large or your computer is processing many steps. Wait for the loading bar to finish. Do not click anything else while it loads.
